## 探测范围

- 探测日期：2026-08-02
- 数据来源：真实接口抓取后的字段结构扫描

## 当前导出 schema

### 合并账单 CSV

固定列顺序：

```text
订单类型、订单号、商品名称、商品模板ID、订单状态、成交数量、成交价格(分)、成交时间、买家昵称、卖家昵称、Steam报价ID
```

### 买入/卖出 CSV

固定列顺序：

```text
订单号、商品名称、订单状态、成交数量、成交价格(分)、成交时间、Steam报价ID、买家昵称、卖家昵称
```

### 前端分析结果 CSV

交易记录部分保留：

```text
成交时间、买家昵称、卖家昵称、Steam报价ID
```

前端还会保留订单号、商品名、模板、类型、金额、状态等分析所需字段。Steam 报价 ID 从 CSV 解析到 `TradeRecord.tradeOfferId` 后进入分析导出。

## 字段映射规则

| 输出字段 | 列表优先字段 | 详情增强后备字段 | 默认状态 |
| --- | --- | --- | --- |
| 订单号 | `orderNo` → `id` → `orderId` | 无 | 保留 |
| 商品名称 | `productDetail.commodityName`、`commodityName` | `_detail.commodity.name` | 保留 |
| 商品模板ID | `productDetail.commodityTemplateId` | `_detail.commodity.templateId` | 保留 |
| 订单状态 | `orderStatusName` → `orderStatus` | 无 | 保留 |
| 成交数量 | `commodityNum` → `commoditySuccessNum` → 商品对象数量 | 无 | 保留 |
| 成交价格(分) | `totalAmount` → `commodityAmount` → `paymentAmount` → 商品价格 | `_detail.commodity.price`、`_detail.revenue.amount` | 保留 |
| 成交时间 | `createOrderTime` → `finishOrderTime` → `paySuccessTime` | `_detail.orderCreatedTime` | 保留 |
| 买家昵称 | `buyerUserName`、兼容 `buyerNickname`/`buyerNickName` | `_detail.buyer.name` | 保留 |
| 卖家昵称 | `sellerUserName`、兼容 `sellerNickname`/`sellerNickName` | `_detail.seller.name` | 保留 |
| Steam报价ID | `tradeOfferId` | `_detail.tradeOfferId` | 保留 |

列表字段优先于详情字段；详情增强默认关闭。开启后只补齐上述紧凑字段，不动态展开数百列，也不写入原始 JSON 文件或原始 JSON 列。

## 暂未映射字段

列表中还探测到大量状态、费用、风控、展示、Steam、营销、售后、按钮和嵌套商品字段。它们保留在字段清单中，暂不直接导出，避免：

- CSV 列数随接口响应变化；
- 嵌套对象被强行序列化为难以使用的字符串；
- 订单隐私字段在没有明确用途时扩大暴露范围；
- 前端分析因为动态列变化而失去兼容性。

后续若需要新增字段，应先在本文件补充映射、确认单位和空值语义，再增加测试和固定列。
